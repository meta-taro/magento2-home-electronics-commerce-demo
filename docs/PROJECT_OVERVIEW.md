# PROJECT OVERVIEW

## 背景

Adobe Commerce / Magento の開発では、テーマ開発だけでなく、独自モジュール開発、DI(`di.xml`)、Plugin、Observer(`events.xml`)、`routes.xml`、REST API、GraphQL、そして ERP / WMS / 決済 / 配送 / CRM といった外部システムとの連携・データ同期が扱われることが多い。

一方で、これらは実際に Magento 環境を構築し、モジュールを書き、イベントをフックし、API を叩いてみないと「分かったつもり」で終わりやすい領域でもある。

そこで本リポジトリでは、架空の家電メーカー「NOVA HOME Electronics」の海外向けECサイトという具体的な題材を設定し、Magento Open Source 上で上記の技術要素を段階的に実装・検証する。作業は Claude Code(AIエージェント)を併用して進め、その過程を学習ログとして残す。

## なぜ Magento Open Source を使うのか

- Adobe Commerce(有償版)と **Magento Open Source は同じコアアーキテクチャ**を共有しており、モジュール構造・DI・Plugin・Observer・レイアウトXML・REST/GraphQL の作法はほぼ共通。Open Source で学んだことは Adobe Commerce の開発にも応用できる。
- 無償で入手でき、ライセンス費用なしにローカル環境を構築できる。
- 公式ドキュメント(DevDocs)が充実しており、一次情報で学べる。
- Adobe Commerce 固有機能(B2B、ページビルダーの一部、Commerce 専用モジュール等)は対象外になるが、基礎〜中級の実装を理解・検証するには十分。

## なぜ家電メーカーの海外ECを題材にするのか

- **海外EC**: マルチストアビュー、複数地域(US / EU / Singapore)、通貨・税・配送の差異など、Magento が得意とする多店舗・多地域構成を自然に扱える。
- **家電メーカー**: 商品属性が豊富(電圧、プラグタイプ、対応フィルター型番、消耗品との関連付けなど)で、商品マスタ設計や属性セット、関連商品の実装題材として適切。
- **メーカー直販**: ERP(受発注・商品マスタ・価格)、WMS(倉庫別在庫・出荷)、決済、配送、CRM/MA との連携が現実的に発生する構成で、データ同期・バッチ取込の検証題材になる。
- 架空メーカーにすることで、商標・実在企業の問題を避けつつ、リアルな業務シナリオを描ける。

## Shopify 学習との違い

| 観点 | Shopify | Magento Open Source(本リポジトリ) |
|------|---------|-------------------------------------|
| 立ち位置 | SaaS。プラットフォーム側がインフラ・コアを管理 | 自前ホスティングの OSS。サーバ・DB・検索エンジン・キャッシュも自分で構成 |
| カスタマイズの粒度 | テーマ(Liquid)、アプリ(API/拡張ポイント)中心 | コアの内部にモジュールとして踏み込める。DI / Plugin / Observer でフレームワーク挙動を差し替え |
| 拡張モデル | アプリ + Webhook + Admin API/Storefront API | 独自モジュール + イベント + Plugin + REST/GraphQL + プラグイン的に差し込む各種 XML 設定 |
| 学べること | フロント・テーマ・アプリ連携・API活用 | 上記に加えて、エンタープライズEC のモジュール設計・DIコンテナ・イベント駆動・複雑なデータ同期 |
| 向いている領域 | 中小〜中規模 EC、スピード重視 | 大規模・要件が複雑・基幹連携ありの EC。設計とフレームワーク理解の比重が大きい |

要約すると、Shopify 学習が「プラットフォームの上でどう作るか」であるのに対し、本リポジトリは「EC プラットフォームそのものの内部構造を理解し、フレームワークの拡張ポイントを使って組み立てる」ことに重心がある。

## 学んだことを整理・説明しやすくするポイント

- 「Magento Open Source で公開学習リポジトリを作り、テーマだけでなく DI / Plugin / Observer / REST / GraphQL / 外部連携 / バッチ同期まで段階的に検証している」と、具体物(GitHub)を示しながら話せる。
- 家電メーカー海外EC という業務シナリオで説明できるので、技術用語だけでなく「何のためにその機能を使うか」を業務文脈で語れる。
- ロードマップ(`docs/ROADMAP.md`)と学習ログ(`docs/LEARNING_LOG.md`)があるので、学習プロセスの計画性・継続性を示せる。
- AIエージェント(Claude Code)を使って未知領域を高速にキャッチアップしつつ、公式ドキュメント確認・動作確認・差分確認・ログ確認を必ず行う、という堅実な進め方を説明できる。
